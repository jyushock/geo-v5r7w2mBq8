# 現在地のなめらかさ 検証結果

`node tests/location-smoother-sim.js 30` の出力（乱数30通り）。旧＝変更前の app.js の補間、新＝`createLocationSmoother`（app.js の `LOCATION_SMOOTHER_BEGIN`〜`END` をそのまま読み込んで検証）。

## 目指した動き（iOS の Google マップ）
- 止まっているとき、点は動かない
- 動いているとき、測位（約1秒ごと）の合間も一定の速さで進み続ける。測位のたびに加速・減速しない
- 予測がずれたときは、位置も速度も途切れない曲線で寄せる（瞬間移動しない）
- 曲がる・止まる・発進するときに、行き過ぎたり置いていかれたりしない
- 60Hz と 120Hz の端末で同じ動き

## 試験の条件
- GPS の誤差：ゆっくり動く相関誤差（標準偏差3m、20秒）＋測位ごとの細かい誤差（2m）＋マルチパスによる20〜60mの飛び（2%）。同じ測位の再送も混ぜる（10%）
- 測位間隔：0.85〜1.15秒。別シナリオで0.5〜3秒の不規則、8秒の途絶
- 端末が返す速度・進行方向：両方あり（屋外の GPS 測位）／速度のみ／どちらもなし（Wi-Fi・基地局の測位）
- 動き：静止、歩行（1.4m/s）、角を曲がる・信号待ち、自転車（5m/s・カーブ）、車（15m/s・発進・カーブ・停止）。加減速は人1.0、自転車1.5、車2.5m/s²まで
- 厳しめの条件：屋内想定（誤差8m、飛び5%）、相関誤差が細かく向きを変える（1次）、マルチパス10%

## 指標
| 指標 | 意味 | 目標 |

| 誤差RMS | 表示と真の位置の差 | 旧以下（5%まで） |
| 静止中のブレ | 止まって3秒以上たってからの、1秒あたりの往復した道のり | 最悪でも 0.02m/s 未満 |
| 静止中の動き | 止まっている間に点が動く速さ（ゆっくり位置を直す動きを含む） | 平均 0.12m/s 未満 |

| 60/120Hz差 | 同じ測位を60Hzと120Hzで描いたときの位置の差 | 1cm 未満 |

## 目標に届かなかったもの
- **端末が速度を返さないとき（3シナリオ）**：位置だけから「歩き出した／止まった」を見分けるには、GPS の誤差（数m）を上回る移動が出るまで待つしかない。そのため歩き出しで約5秒遅れ、その遅れを取り戻すときに速さが揺れる。
  - 静止のブレは平均0.003m/sで、ほぼ消えている。ただし一部の乱数で、マルチパスが続いたときに点が数m動く。
  - 屋外の GPS 測位では、iPhone の Safari も Android の Chrome も速度を返すので、通常の利用でこの状態になるのは主に屋内（Wi-Fi・基地局の測位）。
- **屋内想定の静止中の動き（0.25m/s）**：GPS の位置が±8mでさまようため、点を止めたままにすると誤差が大きくなる。誤差を旧方式以下に保つ範囲で、ゆっくり（0.3m/s以下）位置を直している。往復するブレは0.001m/s。
- **速度のみ（進行方向なし）の歩行**：歩き出しの数秒、向きが定まるまで速さが揺れる（ばらつき0.29、止まって見える割合1.2%、最悪4.6%）。

## 実機相当の確認（ヘッドレス Chromium で app.js 全体を動かし、測位を模擬）
