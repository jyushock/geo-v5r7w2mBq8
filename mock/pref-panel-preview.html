「都道府県から探す」 モック案

数字はすべて castle.js の実データ集計で、全 23,377城すべてを都道府県に振り分けた状態です。 内訳は prefecture 欄 14,997件 ＋ address 先頭一致 8,380件 ＋ address 途中に県名 8件 ＋ 住所付与を再実行すれば国土地理院APIが住所を返す 39件 ＋ API が住所を返さない海上構造物 11件（座標の最近傍で確定）。 枠は iPhone SE3 実寸（375×667）、下部バー52pxを残す先日の変更を反映しています。

入口（共通）

「一覧から探す」に2つ目のボタンを足す。城主から探すと同じ形。サブテキストに総数を出す。

※ ただし39件は、GetTabelog 側で住所付与（Mergers/GeoAddressConverter.cs）を 実行することが前提です。現在 address が空のまま残っている山形県置賜地方の38件と 姫路城は、いま国土地理院APIを叩けば住所が返ります（実測で確認）。 なお 住所付与だけを実行するボタンは現在ありません。これを含む①のボタンは CASTLE_PIPELINE.md が「最初に1回のみ」と規定しており、今のマスターに回すと 同じ城が別キーで重複追加されます。単独実行の口を足すのが前提になります。
※ API が住所を返さないのは11件だけで、すべて海上・海岸線の構造物です （チャシ3・台場/砲台/番所7・館ヶ崎館）。座標が海側にあり市区町村コードが引けないためで、 再実行しても埋まりません。castle_manual_overrides.json は Exclude と FixUrl の 2種類しか持たないため住所の上書きには使えず、項目を足すか、UI 側で座標の最近傍から 決めることになります（未判定11件なら実測7.3ms、k=5の多数決で誤りゼロ）。
※ UI 側の判定コストは実測で 文字列一致だけなら5.0ms（23,435件）。全件を一律に座標から 判定する方式も試しましたが、197msと速い一方で正解率92.1%（県境で1,848件が誤り。愛知→岐阜103件など）で、 都道府県ポリゴンを新たに持たない限り採れません。
※ prefecture と address 先頭が食い違う11件は CASTLE_PIPELINE.md に既知として記載があります（「県境の城6件を除く実質5件」）。 座標の最近傍で調べたところ、7件は address 側、4件は prefecture 欄が 支持されました。
