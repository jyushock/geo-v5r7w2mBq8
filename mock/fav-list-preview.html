お気に入りから検索 — 入口と一覧のモック

決まった案だけを組んだ確定版。入口は「一覧から検索」を4列にして一番右に星、 一覧ビュー・飛ぶ／戻る・空のとき・保存の形は前のモックの案をそのまま採り、 カード配布とお城のキーは名前＠座標4桁にする。
マークは mock/fav-badge-preview.html で決めた4枠（意味を持たせず、名前は設定で付ける。 行は左端の色帯、シートはヘッダー直下のライン）。 枠は iPhone SE3（375×667）を拡大縮小なしで置いてある。

1. 入口（4列の一番右）

.nearby-list-btns の grid-template-columns を repeat(3, 1fr) から repeat(4, 1fr) にして、右端に星を足す。 1本あたり 109px → 79.75px（375px端末：(375 - 16×2 - 8×3) / 4）。 アイコンは34pxなので余裕があり、「お気に入り」5文字×9px＝45pxも収まる。 このクラスを使っているのはこの1か所だけなので、他への波及は無い。

星の地色 #FFC107 は4色のどれでもない。4枠の総称としての入口なので、 特定の枠の色を使うと「お気に入り1だけの入口」に見える。 この色はパネルの中にしか出ないので、地図のポケふた #FBBC04 と並ぶことはない。

2. お気に入り一覧ビュー

城主一覧・都道府県一覧・遺構一覧と同じ枠組み（.lords-head ＋ .lords-filter ＋ .lords-scroll）。絞り込みチップの名前は設定で付けた名前が入る。 下のチップと検索欄は実際に動く。

種別（食べログ・お城…）の絞り込みチップは置いていない。設定の「オブジェクト表示」で消した種別は 地図・検索・周辺検索・都道府県から探す・城主から探すの全部から消える決まりなので、 お気に入り一覧もそれに従わせる（この画面だけ別の種別セットを持たせると規則が二重になる）。

3. 一覧からオブジェクトへ飛ぶ／戻る

行をタップしたときの動きは、県ページの prefJumpToItem() と揃える。 saveListReturnCamera() で今の地図を控える → closeNearby() → onResultClick(item) で寄せて情報シートを開く → 400ms 後に戻り導線を挿す、の順。 戻ると地図も一覧のスクロール位置も飛ぶ前へ戻る。

5. 保存の形（いまはローカル、後でサーバー）

保存先だけ差し替えられるように、読み書きを2つの関数に閉じ込めておく。 いまは localStorage（既存の settingsState ・ nearbyTypeFilterOff と同じ置き場）で、後からサーバーに移すときは この2つの中身だけを差し替える。名前も同じキーに入れる（4枠ぶんの文字列だけなので分ける理由が無い）。

23,516件		castle:{name}@{lng},{lat} 欠落 0 / 衝突 0 url を使わない理由：欠落 19,037件（81%）。 名前だけでも足りない（「松本城」は5件ある）。名前＋座標4桁なら全23,516件で衝突しない

座標は小数4桁（約11m）に丸めてから使う。生の値のまま使うと、データ更新で末尾が1桁動いただけで 別のオブジェクトとして扱われるため。
残る弱点：castle.js を作り直して座標が11m以上動くと、その城のマークは外れる。 長く使うなら castle.js 側に安定IDを振るのが確実で、そのときは castle:{id} へ移し替える（古いキーは名前＠座標のまま読めるので、 移行時に片方向の変換を1回流せばよい）。
サーバーへ移すときは、wrangler.toml の Cloudflare 構成に KV か D1 を足して /api/favorites を作り、上の JSON をそのまま置く形が最短。 ローカルを一次キャッシュ、サーバーを正とし、at（更新時刻）が新しい方を採れば 端末をまたいでも壊れない。
