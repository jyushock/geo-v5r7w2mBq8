# 入力ファイル仕様

TravelPlan が読み込む地点リストファイルの仕様です。
外部アプリからこの形式で出力すれば、そのまま取り込めます。

- 版: 1.0
- 制定: 2026-08-20

---

## 1. 概要

TravelPlan は、訪問したい地点のリストを受け取り、総移動距離が最小になる訪問順序を算出します。
距離は**直線距離（Haversine による大圏距離）**で計算するため、地点ごとに**名前と座標**があれば処理できます。
住所文字列から座標を求める処理（ジオコーディング）は行いません。座標は入力側で用意してください。

- 1ファイル = 1旅程
- 複数の旅程を扱う場合はファイルを分けてください
- 行数の上限はありません（地点数に応じて厳密解と近似解を自動で切り替えます）

---

## 2. ファイル形式

| 項目 | 指定 |
|---|---|
| 形式 | TSV（タブ区切りテキスト） |
| 区切り文字 | タブ `U+0009` |
| 文字コード | UTF-8（BOM の有無は問わない） |
| 改行コード | LF / CRLF のいずれでも可 |
| 1行目 | ヘッダ行（列名）。**必須** |
| 2行目以降 | 1行 = 1地点 |
| 拡張子 | `.tsv` を推奨（`.txt` も可） |

### CSV ではなく TSV とする理由

施設名・メモ・住所には `,` が混入し得ますが、タブが入ることはまずありません。
TSV ならクォートとエスケープの処理が出力側・入力側の双方で不要になります。

CSV しか出力できない場合は [§9](#9-csv--json-で出力する場合) を参照してください。

### 制約

- フィールド内にタブと改行を含めないでください（TSV では表現できません）
- 値の前後の空白は読み込み時に除去されます
- 空行は無視されます

---

## 3. 列の定義

**列の順序は問いません。**ヘッダ行の列名で判定します。
仕様に無い列が含まれていても無視するだけで、エラーにはなりません。

### 3.1 必須列

| 列名 | 型 | 内容 |
|---|---|---|
| `name` | 文字列 | 地点名。表示に使用します。空文字は不可。重複は許容します |
| `lat` | 数値 | 緯度。十進度。北緯が正 |
| `lng` | 数値 | 経度。十進度。東経が正 |

座標の詳細は [§4](#4-座標の指定) を参照してください。

### 3.2 任意列

省略した場合、または値が空の場合は既定値が適用されます。

| 列名 | 型 | 内容 | 既定値 |
|---|---|---|---|
| `role` | 列挙 | `start` / `end` / `via` | `via` |
| `stay` | 整数 | 滞在時間（分）。0以上 | `0` |
| `day` | 整数 | 訪問日の固定指定。1始まり | 空（自動割り当て） |
| `priority` | 列挙 | `must` / `want` | `want` |
| `note` | 文字列 | 自由記述。処理には使用しません | 空 |
| `id` | 文字列 | 一意キー | 自動生成 |

#### `role`

出発地と帰着地を固定するために使用します。

| 値 | 意味 |
|---|---|
| `start` | 出発地。順序の先頭に固定します |
| `end` | 帰着地。順序の末尾に固定します |
| `via` | 経由地。最適化の対象です |

- `start` は最大1行、`end` は最大1行までです
- `start` のみ指定して `end` を省略すると、「出発地固定・終点自由」として扱います
- 往復（出発地に戻る）の場合は、同じ座標の行を `start` と `end` の2行として出力してください
- どちらも省略した場合は、全地点を経由地として扱い、最短の並びを自由に決定します
- 値の大文字小文字は区別しません

#### `stay`

滞在時間です。日ごとの区切りを決める際に、移動時間と合算して使用します。
訪問順序そのものには影響しません（順序は距離のみで決まります）。

#### `day`

特定の日に固定したい地点がある場合に指定します（宿泊予約、時間指定のイベントなど）。
空欄の地点は自動で割り当てます。

#### `priority`

全地点を回りきれない場合の取捨選択に使用します。
`must` は必ず残し、`want` から削ります。

#### `id`

再読み込み時に同一地点として扱うためのキーです。
省略した場合は `name` と座標から自動生成します。
指定する場合はファイル内で一意にしてください。

## 4. 座標の指定

### 4.1 測地系

**WGS84 または JGD2011（日本測地系2011）で出力してください。**

- WGS84 と JGD2011 の差は数cm〜数十cm で、国土地理院は「実用上ほぼ同じものとして扱うことができる」としています。したがってどちらでも構いません
- **旧日本測地系（Tokyo Datum）は使用しないでください。**世界測地系とは約400m（東京付近で約450m）ずれます。これは後述する座標精度の議論を無意味にする大きさです
- 出力元が2001年以前の測量成果や古い地図データを参照している場合のみ、旧日本測地系である可能性があります

### 4.2 表記

**十進度（decimal degrees）で出力してください。**

```
OK    35.68120
NG    35°40'52.3"N     (度分秒。対応しません)
NG    N35.68120        (方位記号付き。対応しません)
NG    35,68120         (小数点にカンマ。対応しません)
```

南緯・西経は負値で表記しますが、日本国内であれば発生しません。

### 4.3 精度

緯度1度は約 111.2 km です。小数点以下の桁数と誤差の対応は次の通りです。

| 小数点以下 | 緯度方向の誤差 | 判定 |
|---|---|---|
| 2桁 | 約 1,110 m | 不足 |
| 3桁 | 約 111 m | 順序の決定には足りるが、地図表示でズレが見える |
| **4桁** | 約 11 m | **最低ライン** |
| **5桁** | 約 1.1 m | **推奨** |
| 6桁以上 | 約 0.11 m 以下 | 不要（GPS の実用精度を超えます） |

**推奨は小数点以下5桁、最低4桁です。**

経度方向の誤差は緯度が高いほど小さくなります（北緯35度で緯度方向の約0.82倍、北緯45度で約0.71倍）。
したがって緯度を基準に桁数を決めれば、経度側は自動的に足ります。

訪問順序の決定という目的だけを見れば3桁（約111m）でも結論は変わりません。
4〜5桁を推奨するのは、地図上にピンを描画したときに実際の建物とズレて見えないようにするためです。

## 5. 検証ルール

読み込み時に以下を検証します。

### 5.1 エラー（読み込みを中止します）

| 条件 | 内容 |
|---|---|
| ヘッダ行が無い | 1行目が列名として解釈できない |
| 必須列の欠落 | `name` / `lat` / `lng` のいずれかが存在しない |
| `name` が空 | 空文字または空白のみ |
| 座標が数値でない | 十進度としてパースできない |
| 緯度が範囲外 | `lat` が -90 〜 90 の外 |
| 経度が範囲外 | `lng` が -180 〜 180 の外 |
| `role` の重複 | `start` が2行以上、または `end` が2行以上 |
| `id` の重複 | 明示指定した `id` がファイル内で重複 |
| 有効な地点が0件 | データ行が1行も無い |

### 5.2 警告（読み込みは継続します）

| 条件 | 意図 |
|---|---|
| `lat` > 90 だが `lng` として妥当 | 緯度と経度の入れ替わりの検出 |
| 緯度が 20〜46 度、経度が 122〜154 度の外 | 桁の間違い、測地系の取り違えの検出 |
| 座標の小数点以下が3桁以下 | 精度不足の通知 |
| 同一座標の地点が複数 | 重複出力の検出 |
| `stay` / `day` が整数でない | 既定値を適用したことの通知 |
| `priority` / `role` が未定義の値 | 既定値を適用したことの通知 |

緯度20〜46度・経度122〜154度は**日本のおおよその範囲を示す目安**です。
厳密な国境判定ではなく、桁の間違いや緯度経度の入れ替わりを検出するための緩いチェックとして使用します。
この範囲を外れても読み込みは継続します。

---

## 6. 読み込み側で吸収する範囲

出力側で神経質にならなくて済むよう、以下は自動的に処理します。

- 値の前後の空白、タブ以外の空白文字
- 空行
- BOM の有無
- LF / CRLF の違い
- 列の順序
- 仕様に無い列の混在
- 列名の大文字小文字（`Name` / `NAME` / `name` は同一とみなす）
- `role` / `priority` の値の大文字小文字
- 列名の別名（下表）

### 認識する列名の別名

| 正式名 | 別名 |
|---|---|
| `name` | `title`, `label`, `名前`, `名称`, `地点名` |
| `lat` | `latitude`, `緯度` |
| `lng` | `lon`, `long`, `longitude`, `経度` |
| `stay` | `duration`, `滞在時間` |
| `note` | `memo`, `comment`, `備考` |

## 7. サンプル

タブ区切りです（以下の表示ではタブが空白に見える場合があります）。

```
name	lat	lng	role	stay	priority	note
自宅	35.68120	139.76710	start	0	must
目的地A	34.98530	135.75850	via	90	must
目的地B	34.66780	135.50120	via	60	want	昼食
目的地C	34.39530	132.45530	via	45	want
自宅	35.68120	139.76710	end	0	must
```

必須列のみの最小構成も有効です。

```
name	lat	lng
目的地A	34.98530	135.75850
目的地B	34.66780	135.50120
目的地C	34.39530	132.45530
```

> 上記の座標は**形式を示すためのダミー**であり、実測値ではありません。

## 8. 出力側チェックリスト

外部アプリ側で出力を実装する際の確認項目です。

- [ ] 文字コードは UTF-8 か
- [ ] 区切り文字はタブか（半角スペースや全角スペースになっていないか）
- [ ] 1行目にヘッダ行があるか
- [ ] `name` / `lat` / `lng` の3列が揃っているか
- [ ] 座標は十進度か（度分秒になっていないか）
- [ ] 座標は WGS84 / JGD2011 か（旧日本測地系ではないか）
- [ ] 小数点以下4桁以上あるか
- [ ] 緯度と経度が入れ替わっていないか
- [ ] フィールド内にタブや改行が混入していないか
- [ ] `role=start` / `role=end` がそれぞれ最大1行か

## 9. CSV / JSON で出力する場合

TSV を推奨しますが、以下も受け付けます。列の定義と座標の規約は TSV と共通です。

### CSV

- RFC 4180 準拠とします
- フィールドは必要に応じて `"` で囲み、フィールド内の `"` は `""` にエスケープします
- 文字コードは UTF-8
- 拡張子は `.csv`

### JSON

- 配列のトップレベルに、地点を表すオブジェクトを並べます
- キー名は TSV の列名と同一です
- 数値は文字列ではなく数値型で記述してください

```json
[
  { "name": "自宅",     "lat": 35.68120, "lng": 139.76710, "role": "start" },
  { "name": "目的地A",  "lat": 34.98530, "lng": 135.75850, "stay": 90, "priority": "must" },
  { "name": "目的地B",  "lat": 34.66780, "lng": 135.50120, "stay": 60, "note": "昼食" },
  { "name": "自宅",     "lat": 35.68120, "lng": 139.76710, "role": "end" }
]
```

## 10. 仕様の根拠

本仕様の判断根拠となった一次情報です。

| 項目 | 出典 |
|---|---|
| WGS84 と JGD2011 が実用上同一であること、旧日本測地系との差 | [測地系 \| 国土地理院](https://www.gsi.go.jp/sokuchikijun/datum-main.html) |
| 旧日本測地系と世界測地系のずれが約400m（東京付近で約450m）であること | [測地系とは？ \| ゼンリンデータコム](https://www.zenrin-datacom.net/solution/blog/geodetic-system) |
| CSV のクォート・エスケープ規約 | RFC 4180 |

座標精度の対応表（§4.3）は、緯度1度を約 111.2 km（球面近似：`2πR/360`, `R = 6371 km`）として算出した値です。
