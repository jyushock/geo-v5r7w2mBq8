食べログのジャンルを種別項目化 — UI案

実データ（data.js 7,077件）を全件調べた結果です。ジャンルの候補が2種類あり、両者は一致しません。 どちらを使うかで見た目も件数も変わるので、案の中で並べています。

候補出どころ種類例（同じ店で）
A 部門（category から地名を外したもの）100名店の部門。category「ラーメン（東京）」35種ラーメン
B 店ジャンル（name 末尾の括弧）食べログ店舗ページの h1。name「… - 蒲田（つけ麺）」100種つけ麺

確認できた事実 ― name は7,077件すべてが「店名 - 駅（ジャンル）」に合致（正規表現で全件検査。例外0件）。 category の括弧内は必ず地域名（北海道・東京・神奈川・愛知・大阪・香川・東日本・西日本の8種のみ）で、 外すと35種に畳まれます。地図のラベルは ['get','name'] で name をそのまま出しているので、 name を書き換えなければ地図の文言は変わりません（シート側だけ整形すれば足ります）。

1. 情報シート S4（決定）— 部門と地域の出し方 4案

決まったこと：ジャンル源はA 部門（category から地名を外した35種）、シートはS4 バッジ＋項目。 残るのは「部門をバッジに出すと、賞の正式名（ラーメン（東京））と同じ情報が2つ出る」点で、その始末が4案あります。 上段は普通の店、下段は実データで最も条件が厳しい店（部門14文字＋店名が長い）です。

3. 懸念事項（category の地名）について

地名は外せます。ただし category 自体は残す方が安全です。
括弧内は8種の地域名しか現れないため、category.replace(/（[^（）]*）\s*$/, '') で機械的に外せます（全71種で検査済み）。 一方 category そのものは「ラーメン 東京 百名店に選ばれた」という賞の情報なので、消すと出どころが失われます。 表示側で「部門」を導出する形にすれば、data.js を作り直さずに今日から使えます。

生成側（GetTabelog）に新フィールドを足す案との比較
ShopDataJsWriter に genre（地名なし部門）や station を持たせることもできますが、 data.js の再生成が要ります。値は既存 category から導出できるので新規スクレイピングは不要です。 表示側で導出 → 動きを確かめてから、必要なら生成側に移すのが手戻りが少ないです。

B（店ジャンル）を使う場合は name のパースが必要です。
全件パターン一致は確認済みですが、これは「今のデータで100%」であって、将来の取得分でも成り立つ保証はありません （店名に「 - 」や全角括弧が入る店が現れると崩れます）。フィルターの土台にするなら、 生成側で店名・駅・ジャンルを分けて持たせる方が堅いです。
